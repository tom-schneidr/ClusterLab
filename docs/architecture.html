ClusterLab Architecture

ClusterLab is a local-first FastAPI application with a static browser client, SQLite persistence, and an OpenAI-compatible LLM provider boundary.

Runtime Shape

  • app.py exposes the ASGI application for Uvicorn.
  • clusterlab/app_factory.py constructs the FastAPI app, static file mount, database store, and API router.
  • clusterlab/api/ owns HTTP routes and request schemas.
  • clusterlab/engine.py owns run orchestration and blackboard updates.
  • clusterlab/topology.py owns graph role lookup, edge traversal, and topology validation.
  • clusterlab/storage.py persists hats, topologies, runs, and run events in SQLite.
  • clusterlab/llm.py calls an OpenAI-compatible /chat/completions endpoint.

Frontend Shape

The frontend intentionally stays build-free while the project is small. static/app.js contains UI behavior, while shared primitives live in static/js/.

static/js/api.js        API helper
static/js/constants.js  graph constants, tool IDs, palette templates
static/js/dom.js        DOM and formatting helpers
static/js/state.js      shared mutable UI state

Run Lifecycle

  1. The UI saves or selects a topology.
  2. POST /api/runs/start loads the topology and hats from SQLite.
  3. The engine validates the topology and builds a stage plan.
  4. Each hat receives a prompt built from the task, stage, typed edges, upstream outputs, and compact blackboard.
  5. Outputs are appended as run events and selectively written back to the blackboard.
  6. The final result is persisted on the run and returned with the event trace.

Growth Rules

  • Keep route handlers thin; move business logic into domain modules.
  • Add tests at API, storage, topology, and engine boundaries before large behavior changes.
  • Keep SQLite until multi-user or remote deployment requirements are concrete.
  • Keep vanilla JavaScript until UI complexity justifies a build step.
  • Prefer explicit migrations before changing persisted schema.
